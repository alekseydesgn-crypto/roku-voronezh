# Управление ROKU через Pages CMS

## Первый вход владельца

1. Открыть /admin/ на сайте или https://app.pagescms.org/.
2. Войти через GitHub аккаунтом `alekseydesgn-crypto`.
3. Установить GitHub App Pages CMS, выбрав **Only select repositories → roku-voronezh**. Доступ к остальным репозиториям не нужен. Приложение получает возможность изменять содержимое выбранного репозитория — подключение подтверждает владелец аккаунта.
4. Открыть `roku-voronezh`, ветку `main`. Конфигурация `.pages.yml` уже подготовлена.
5. Проверить изменение текста, сохранить, дождаться публикации GitHub Pages и проверить сайт. Без этого первого подключения авторизация/запись в CMS не подтверждены.

## Разделы админки

- **Тексты, акция и контакты** — SEO, соцсети VK/Telegram, первый экран, знакомство, сервис, игровое пространство, кухня, лаунж, акция открытия, контакты. Перенос строки задаётся клавишей Enter в многострочных полях. HTML не нужен.
- **Игровые зоны и характеристики** — название, категория, описание, пометка визуализации, фотографии, пары «параметр — значение». По умолчанию оставлено по одной прежней визуализации без автолистания. Дополнительные фото доступны только внутри открываемой галереи.
- **Фото главной, кухни и лаунжа** — загрузка, замена и порядок фотографий. Желательно загружать WebP/JPEG до 300–500 КБ, шириной 1600–1920 px.

## Публикация и ограничения

CMS сохраняет публичный контент и фотографии в GitHub. Не помещайте в контент заявки, пароли и персональные данные гостей. Получение заявок — отдельная интеграция; текущая форма остаётся демонстрационной.

GitHub Pages сохраняет прежнюю публикацию из ветки `main` / корня. Отдельный сервер, API-ключ в браузере или сборка не требуются. `cms-content.js` читает JSON с того же сайта перед запуском интерактивных элементов. При недоступности/ошибке файла применяются исходные тексты и фото из HTML/JS; неисправный набор зон/фото не подменяет рабочую версию. Обновлённый контент появляется после публикации Pages и обновления страницы. Статический HTML остаётся запасной версией, поэтому отдельным поисковым роботам/просмотрам без JavaScript может быть доступен исходный текст.

Дизайн и произвольные новые разделы редактируются в коде. Админка управляет существующими блоками. История Git позволяет вернуть предыдущую редакцию файлов.

Доступ маркетолога/клиента назначается отдельно через Pages CMS. Не передавайте пароль владельца GitHub.

Документация: https://pagescms.org/docs/quick-start/ и https://pagescms.org/docs/configuration/.
